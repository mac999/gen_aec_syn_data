# kcbench 이어서 작업하기: 생성기 v0.5.4가 바꾼 것과 남은 일

작성 2026-11-24. 생성기 gen_aec_syn_data 기준 커밋 `ab890d4`.
kcbench 쪽 담당자가 읽는 문서다. 재생성 실행 절차 자체는
`doc/handoff_v054.md`에 있고, 여기서는 **kcbench가 소비하는 데이터가 어떻게
달라지는지**와 **kcbench 쪽에 남은 일**만 다룬다.

## 1. 맥락 — kcbench의 발견이 생성기를 바꿨다

worked-example-4의 진단이 이번 수정의 출발점이다: v0.5.3 STaR 12,725행 중
refusal 2,346행(18.4%, v0.5.2는 0.1%)이 블랭킷 거절을 가르쳐, 학습 모델이
지문이 있는 uc6_v2 문항의 60%를 거절했고 uc6 점수가 0.631→0.244로
무너졌다. 5% cap 학습으로도 복구되지 않았다 — 데이터 자체를 고쳐야 했다.
생성기 커밋 11개(`d0af2bd`~`ab890d4`)가 그 수정이다.

## 2. v054 데이터에서 kcbench가 마주칠 변화

### 행 형식 (채굴·분할 코드에 직접 영향)

- **id 형식이 바뀐다**: `sft_000001` → `<문서폴더명>#<n>` (문서별 번호).
  id가 실행 전역 순번이라는 가정이 코드에 있으면 v054를 읽기 전에 고칠 것.
  대신 재실행·부분 재생성에도 다른 문서의 id가 안 바뀐다.
- **최상위 메타가 생긴다**: `doc_id`, `chunk_index`, `source_date`,
  `version`("v0.5.4"), `license`(기본 "unknown"). generated_dir에서 문서를
  역추적하던 휴리스틱은 더 이상 필요 없다 — doc_id를 그대로 쓰면 된다.
  v053 행에는 이 필드가 없으므로 두 버전을 섞어 읽는 코드는 .get()으로.

### refusal 행의 의미가 다르다 (재채점 규칙에 영향)

- v054의 refusal 행은 모델이 지어낸 질문이 아니라 **검증된 grounded_rag QA의
  쌍둥이**다: 같은 질문, 골든 청크를 뺀 distractor 블록 context, 거절 템플릿
  답("제시된 자료만으로는 확인할 수 없습니다. {doc}의 {section} 조문이
  필요합니다."). 원 답의 수치·조항이 distractor에 하나라도 있으면 생성되지
  않으므로 "이 context로 답 불가"가 구성으로 보장된다.
- **거절 답이 조항 번호를 포함할 수 있다** — 출처를 요구하는 형태로만.
  강화된 검증기 규칙: 거절 문구 필수, 수치 단정 금지, 조항 인용은
  "…필요합니다/참조하십시오" 꼬리가 붙은 포인터만 허용. kcbench에서 refusal
  행을 자체 채점한다면 이 규칙을 전제로 볼 것 (`src/verifiers.py:verify_refusal`).
- sft_tasks에서 refusal 태스크 자체는 제거됐다(6종). STaR 통과분의 refusal
  비중은 `star_task_share_cap`으로 8% 상한.

### 행 수·분포 변화 (비교 분석 시 참고)

- **SFT 행이 v053보다 줄어든다** — 쓰기 전 numbers/citations 게이트가 생겨
  탈락분이 `sllm_rejected.jsonl`(신규 파일)로 빠진다. 줄어든 것이 정상.
- 긴 문서의 행이 앞쪽 페이지에 몰리지 않는다 — 예산을 청크 stride로 전체에
  분배 (v053은 418청크 시방서가 앞 4.3%에서만 나왔음).
- RLVR의 source가 문서 전체인 행이 사라진다 (v053은 24/159가 10만 자 source).
- DPO 쌍은 STaR 통과분에서만 나온다. 연도·횟수 섭동, 조사 잔여물,
  목차형 chosen이 제거된다.
- PDF 추출이 페이지 경계 문장을 봉합하고 그림자 겹침("2년"→"22년")을 접는다.
  **청크 길이는 700 유지** — kcbench 키가 700자 청크 기준이라 바꾸지 않았다.

## 3. kcbench 쪽에 남은 일

1. **holdout.json 제공** (재생성의 선행 조건). 생성기 config_v054.json이
   `../kcbench/ground_truth_v053/holdout.json`을 읽는다. 최근 kcbench 커밋이
   홀드아웃을 규정 패밀리 단위로 넓혔으므로(7d0ef0a), **어느 버전의
   holdout.json을 생성기에 줄지 결정**해야 한다. 생성기는
   `pdf_documents[*].generated_dir`만 읽는다. 파일이 없으면 생성기는
   의도적으로 실행을 중단한다.
2. **id 가정 점검.** 분할·채굴·dedup 코드에서 `sft_\d+` 패턴이나 전역 순번
   가정을 찾는다. v054부터 `doc_id` 필드를 직접 쓰도록 바꾸는 쪽이 간단하다.
3. **v054 수신 후**: 분할 → 학습 → 채점 재실행. 확인할 핵심:
   - **uc6 verdict 회복 여부** — 이번 수정 전체가 겨냥한 지표. abstention율이
     v052 수준(2~6%)으로 돌아왔는지, 지문 있는 문항의 거절이 사라졌는지.
   - uc4 faithfulness 회복 (v053 전체 세트에서 0.931→0.725로 하락했었음).
   - recall형 트랙(probe, track2)이 v053의 이득(0.808, 0.830)을 유지하는지 —
     행 수가 줄어든 대가로 잃는 것이 없는지.
   - 시드 반복: v053에서 같은 2,202행 부분표본이 시드에 따라 abstention
     8%/18%/84%로 흔들렸다. v054 쌍둥이 데이터에서 이 분산이 줄었는지가
     "구성 보장" 접근의 직접 검증이다.
4. **ground_truth_v054 키 구축** 여부 결정. 추출 수정(페이지 봉합·그림자
   접기)으로 청크 내용이 조금 달라지므로, v053 키로 v054 학습 모델을 재는
   것은 가능하되 키 채굴을 다시 하면 문항 품질이 오른다. 트레이드오프:
   키를 다시 만들면 v053과의 전후 비교가 끊긴다. **권고: 1차 비교는 v053
   키로(전후 비교 유지), 키 재구축은 그 다음에.**
5. **결과를 생성기 쪽으로 회신**: uc6/uc4 회복 수치와 남은 문제.
   refusal 쌍둥이 비율(0.3)이나 cap(8%)의 조정이 필요하면 config 값만
   바꾸면 된다 — 코드 수정 불필요.
